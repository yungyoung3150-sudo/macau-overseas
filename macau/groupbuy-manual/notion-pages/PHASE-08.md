## STEP-23 · 공구 운영 중 CS 대응

공구 오픈 이후 fulfillment 구간 내내 들어오는 취소·추가구매·인플 질문·결항·노쇼·예약확정 문의를 실시간 처리하고, 반복 문의는 템플릿으로 누적한다.

**목적**
공구 오픈부터 fulfillment 종료까지 들어오는 모든 CS 문의를 유형별로 실시간 처리하고, 반복 문의를 템플릿으로 누적해 다음 공구에서 더 빠르게 대응한다.

**담당**
- 메인: 김용성, 정민님

**절차**
1. 문의 채널을 모니터링하며 유형별로 분류해 응대한다.
	- **취소 문의** — 아래 ⑤ 취소 정책 확인 후 안내
	- **추가 구매·인펀트 추가** — 추가결제 링크 생성 후 전달 (아래 ②)
	- **인플루언서 질문** — 빠른 대응 (우선순위 최상)
	- **결항 문의** — 아래 ③ 결항 대응 멘트 활용
	- **No Show** — 아래 ④ No Show 안내 참고
	- **예약 확정 언제냐** — 아래 ① 예약 확정 안내 멘트 활용
2. 반복되는 문의는 **템플릿화**해서 다음 공구에 더 빠르게 쓸 수 있도록 누적한다.
3. 변경·취소·환불 건은 임의 판단하지 말고 사내 확정 정책(아래 ⑤ 및 부분환불·취소 방법)에 따라 처리한다.
4. 처리 내용은 CS 로그에 누가·언제·무엇을·어떻게 응대했는지 기록한다.

<callout icon="💡" color="gray_bg">
	**진행상황 상시 공유 (PHASE 08 전 구간 적용)** 이 구간 내내 완료율 등 진행상황을 인플에게 상시 공유한다. CS 응대도 그 흐름의 일부로 본다.
</callout>

### CS 대응 멘트 모음

**① 예약 확정 언제 되냐는 문의**

```
안녕하세요 고객님

저희 예스트래블에서는 총 2가지의 예약 확정 문자가 있습니다.

1. 예약 확정 전 안내 문자:
예약 가능 여부 체크 후, 가능하다고 판단되어 예약을 넣기 전
요청 주신 고객님들께 예약 확정 동의 여부 체크를 위해 전화드리는 것입니다.

2. 최종 예약 확정 안내 문자:
예약 확정이 이미 진행된 상태에서 고객님 출국일 1주일 전
고객님의 항공권 번호, 호텔 예약 번호, 그 외 정보들이 포함된 안내 문자를 보내드립니다.

요청 사항으로 '예약 확정 후 꼭 연락 주세요' 등이 없으시면
자동 확정 진행되고 있어 따로 연락드리지 않고 있습니다.
```

**② 추가결제 링크 생성 방법 (인펀트 추가 등)**

```
JBS 접속 → '예트X추가결제' 탭 선택
→ 품목 > 품목관리 > 추가결제 탭 아무거나 복제 > 수정하기
→ 상품 이름: OOO님의 추가 결제
→ 상품 대표 가격 (보통 인펀트: 16만원)
→ 스크롤 다운 후 판매 항목에서 결제 금액 재수정
→ 수량 설정 1개로 맞추기
→ 적용하기 클릭 → 링크 버튼으로 복사 → 고객에게 전달
```

**③ 결항 대응 (항공사 유류세 이슈 등)**

```
마카오 건으로 연락드린 예스트래블입니다.

현재 고객님 여정 [OOO], [OOO] 부분이 항공사 측 유류세 이슈로 결항되었습니다.

항공사 측에서 대체 항공편으로 변경 예정입니다.
변경 일정이 안 되시면 100% 취소도 도와드릴 수 있습니다.
```

상황 2 — 대체 항공편 없을 때

```
항공사 측 유류세 인상으로 인한 적자 부담으로 결항 시켰습니다.
고객님 예약 취소로 안내드려야 할 것 같습니다.
취소의 경우 결제하신 금액 그대로 환불 예정입니다.
```

쪼기 해피콜 멘트 (간이버전): "해당 상품 현재 유류세 인상으로 인해 결항이 많이 진행되고 있습니다."

```
에어마카오의 경우, 출발편 탑승을 안 하시면 귀국편 항공권이 비활성화 처리됩니다.
출발편 개인적으로 이동 → 귀국편 기존 예약대로 이용은 성립하지 않습니다.
이 점 반드시 고객님께 인지시켜 드려야 이후 문제 소지가 없습니다.
```

**⑤ 취소 정책 (질병·질환으로 인한 취소)**

<callout icon="⚠️" color="red_bg">
	**응대 실수는 인플 관계 단절로 직결된다** 응대 실수 → 고객 불만 → 인플루언서에게 전달 → 관계 끊어질 수 있음. 모를 땐 정민님(사수) 확인 후 답변(혼자 판단 금지). 결항·취소 시 정책 숙지 안 하고 안내하면 금전 문제로 직결.
</callout>

<callout icon="⚠️" color="red_bg">
	**변경·취소·환불은 임의 처리 금지** 변경/취소/환불 건은 반드시 사내 확정 정책·환불 절차를 따른다. 자의적 판단으로 안내하면 분쟁·손실로 이어질 수 있다.
</callout>

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** CS 문의 채널(어떤 메신저/폼/전화)과 CS 로그 기록 위치는 사내 확정값으로 채울 것.
</callout>

**핵심 용어**: 공구 — 인플루언서 커머스 공동구매 · JBS — 추가결제 링크 생성 시 사용하는 예약 시스템 · 인펀트 — 만 2세 미만 유아(추가결제 대상) · 자동확정 — 별도 연락 요청이 없으면 출국 1주일 전 안내까지 자동 진행되는 확정 흐름 · 해피콜 — 예약 확정 전 고객 동의·정보 확인 통화

## STEP-24 · 72시간 후 예약 확정 (해피콜·자동확정)

구매 후 72시간이 지난 건의 항공·호텔 실제 예약 가능 여부를 재확인 → 가능 시 자동 확정(예약 진행), 불가 시 즉시 명확히 안내.

**목적**
구매 후 72시간이 지난 건의 항공·호텔 실제 예약 가능 여부를 재확인하고, 가능하면 자동 확정(예약 진행), 불가하면 즉시 명확히 안내한다.

**담당**
- 메인: 김용성, 정민님

**절차**

전체 흐름

```
예약에 필요한 사이트 준비
→ 고객 명단에서 일정 확인
→ 항공권 구매 가능 여부 체크
→ 호텔 객실 구매 가능 여부 체크
→ 호텔 가능하면 바로 Reserve 누름
→ 총 결제 금액이 공구 시트 금액과 일치하는지 확인
→ 결제 카드 등록
→ 고객 개인정보 국적 먼저 수정
→ 고객 명단(해피콜 시트) 확인 → 성·이름 복사 붙이기
→ 호텔 예약 확정
→ 공구 스프레드시트에서 상태를 '해피콜 완료' 체크
```

상세 절차

1. **72시간 도래 건 추출 & 사이트 준비**
	- 구매 후 **+72시간**이 지난 건(건별 기준)을 해피콜 시트에서 추출 → 자동 확정 절차 시작.
	- 해피콜 메모에 요청 있는 고객(예: "예약 확정 전 꼭 전화 주세요")은 전화 후 진행, 그 외는 자동 확정으로 진행.
	- 마카오 호텔 부킹: [shijicloud 부킹]([내부 시스템 주소 삭제])
	- 에어마카오 좌석 수량: [모객현황 스프레드시트]([내부 링크 삭제])
	- 마카오 해피콜 시트: [해피콜 시트]([내부 링크 삭제])
	- 해당 공구 스프레드시트
2. **고객 명단 일정 확인**
	- 출국일·귀국일 확인 → 2박3일 or 3박4일 구분
	- 인원 수 확인 (수량 체크)
	- 성인 3명 조회 불가 → 성인 2 + 소인 1로 예약 후 호텔 측에 성인 3명이라고 별도 고지
3. **항공 예약 가능 여부 확인 (가용 확인 채널)**
	- **에어마카오** — 모객현황 구글 스프레드에서 해당 일정 좌석 가용 여부 체크
	- **에어부산** — 단톡방에 확정 가능 여부 요청
	- 채널마다 확인 방법이 다름 — 혼동 주의
4. **호텔 객실 가용 여부 체크**
	- New Booking → Room Availability → 선택 사항 입력
	- 성인 2명 이상 조회 불가 → 성인 2명 + 객실 수 올리기
	- **조식 포함/미포함 구분 확인 필수** (가격 차이 큼)
	- 예약 가능 → **Reserve 버튼 클릭**
	- 특이 요청 사항 확인 (예: "예약 확정 전 꼭 전화 주세요")
	- 갤럭시(안다즈/브로드웨이) 물량 부족 시 → 갤럭시 담당자님께 추가 물량 요청 / 리스보아는 리스보아 담당 이사님께 확인
5. **호텔 예약 대금 지불**
	- 결제 카드 등 자격증명은 사내 보안노트 별도 — 담당자에게 요청
	- 카드 종류: MA (번호·만료·명의는 보안노트 참조)
	- 객실 금액(MOP)과 공구 스프레드 결제 금액 일치 확인
	- 고객 국적 KR로 변경
	- 마카오 해피콜 시트에서 성·이름 복붙 후 결제
6. **최종 확정 처리**
	- 공구 스프레드 → 상태: **해피콜 완료** 변경 (건별 확정/불가/보류 기록)
	- 확정 불가 시 → 항공·호텔 재요청 or 고객에게 날짜 변경 유도 → **즉시·명확히 안내** (다음: STEP-25 중간 확정 안내 문자)

<callout icon="⚠️" color="red_bg">
	**호텔 투숙 규정 (예약 세팅 시 필수 확인)** **안다즈 마카오** — 성인 3명 이상 = Extra Bed 자동 발생(원하지 않아도 추가비용) / 성인 2+소인 2 = 추가요금 없음. 시스템에서 성인 3 입력 불가 → 성인 2+소인 1로 조회 후 예약. Extra Bed 발생 시 갤럭시 어드민으로 이메일(Extra Bed request) 필수. 안다즈 Admin은 취소·변경 불가(예약만 가능). **브로드웨이 마카오** — 성인 2+소인 1 = MAX(엑스트라베드 공간 없음) / 성인 3명 = 객실 2개 필요. 성인 5명이면 객실 2~3개 필요 → 고객 사전 안내 필수.
</callout>

<callout icon="⚠️" color="red_bg">
	**주의사항** 대금과 연결되어 있으므로 항상 더블체크, 빠르게 하지 말고 천천히. 72시간 기준 정확히 체크 — 72시간 이전 확정 시 취소 수수료 발생 가능. 확정 불가 건은 고객에게 빠르게 안내(대기 길어지면 CS 악화). 해피콜 메모 확인 — 요청 있는 고객은 전화 후 진행. SCM 확인 없이 확정 금지 → 오버부킹 시 전액 보상 책임.
</callout>

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 신 흐름의 분기 정의가 사내 실제 운영과 맞는지 확정 필요(맞으면 본문 고정). 해피콜(전화) vs 자동 확정 분기 기준 — 어떤 조건/건이 해피콜로 가고 어떤 건이 자동 확정인지(현재 운영: 해피콜 메모에 요청 있는 건만 전화, 그 외 자동). 자동 확정의 정확한 동작 — 무엇이 자동 처리되고 어디서 트리거되는지.
</callout>

**핵심 용어**: 해피콜 — 예약 확정 전 고객 확인 전화·확정 처리 · 자동확정 — 72시간 경과 건을 전화 없이 예약 진행·확정 · 공구 — 인플루언서 커머스 공동구매 · SCM — 호텔 객실 재고 관리 채널

**관련 문서**: 고객 예약 확정 프로세스 · 쪼기 해피콜 멘트 · SCM 부킹 조회 방법 · 마카오 패키지 핵심 정보 · 보안노트(자격증명·카드)

## STEP-25 · 중간 확정 안내 문자 발송

자동 확정 진행 중인 고객에게 중간 확정 안내 문자를 단체 발송해, 최종 확정 정보가 나오기 전 '침묵 구간'의 불안·컴플레인을 줄인다.

**목적**
자동 확정 진행 중인 고객에게 중간 확정 안내 문자를 단체 발송해, 최종 확정 정보가 나오기 전 '침묵 구간'의 불안·컴플레인을 줄인다.

**담당**
- 메인: 김용성, 정민님

**절차**
1. STEP-24 해피콜 완료(자동 확정) 고객 리스트 정리.
2. 미확정 고객과 확정 고객을 명확히 구분 (혼용 금지).
3. 확정 고객에게 중간 확정 안내 문자 단체 발송.
4. 발송 대상·발송 완료 여부를 기록으로 남긴다.

중간 확정 안내 시 참고 — 예약 확정 문자 2종 구분 (고객이 "예약 확정 문자는 언제 오냐"고 물을 때 안내):

```
저희 예스트래블에서는 총 2가지의 예약 확정 문자가 있습니다.

1. 예약 확정 전 안내 문자 (이 단계 / STEP-25):
예약 가능 여부 체크 후, 가능하다고 판단되어 예약을 넣기 전
요청 주신 고객님들께 예약 확정 동의 여부를 확인하기 위해 전화드리는 것입니다.

2. 최종 예약 확정 안내 문자 (STEP-30):
예약 확정이 이미 진행된 상태에서 고객님 출국일 1주일 전
항공권 번호, 호텔 예약 번호 등이 포함된 안내 문자를 보내드립니다.

요청 사항으로 '예약 확정 후 꼭 연락 주세요' 등이 없으시면
자동 확정 진행되고 있어 따로 연락드리지 않고 있습니다.
```

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 중간 확정 문자의 발송 시점 기준(예: 자동 확정 절차 진입 후 며칠)과 단체 발송용 실문구 템플릿은 기존 노트에 명시돼 있지 않다. 확정된 운영 기준·템플릿이 있으면 CS 대응 문자 패턴에 맞춰 채운다.
</callout>

<callout icon="⚠️" color="red_bg">
	**미확정 고객에게 확정 문자 발송 금지** 미확정 고객에게 실수로 확정 문자 발송 금지 — 리스트를 정확하게 구분한 뒤 발송한다. 이 단계는 최종 확정 안내(STEP-30)와 다르다 — 중간 안내 단계임을 인지하고, 항공권 번호·호텔 예약번호 등 최종 정보는 아직 포함하지 않는다.
</callout>

**핵심 용어**: 중간확정 — 최종 확정 정보 전, 진행 상황을 알리는 중간 안내 단계 · 자동확정 — 별도 연락 요청이 없으면 해피콜 후 자동으로 확정 진행 · 해피콜 — 예약 확정 동의 여부를 전화로 확인하는 절차 · 공구 — 인플루언서 커머스 공동구매

**관련 문서**: 예약 확정 문자 대응 · 고객 예약 확정 프로세스 · CS 대응 문자 패턴 · Phase 08 CS·예약 확정 전체

## STEP-26 · 여권정보 미입력 고객 독촉 문자

발권에 필요한 여권정보 미입력 고객을 추려 입력 요청 문자를 발송, 발권 누락을 막는다. 목표는 여권 미입력자 0.

**목적**
발권에 필요한 여권정보 미입력 고객을 추려 입력 요청 문자를 발송해 발권 누락을 막는다. 목표는 여권 미입력자 0.

**담당**
- 메인: 김용성
- 지원: 정민

**절차**
1. 예약 폼(STEP-17에서 세팅한 공구별 신규 구글폼) 응답 데이터 확인
	- 현재 사용 중인 여권 수집 폼 링크:
		- 마카오 일반: [폼 링크]([내부 링크 삭제])
		- 마카오 리스보아: [폼 링크]([내부 링크 삭제])
	- 폼 링크가 직전 공구 것이면 STEP-17에서 교체했는지 먼저 확인(이전 공구 폼으로 수집 시 대형 CS)
2. 폼 응답과 STEP-25 중간 확정 명단을 대조해 **여권정보 미입력자 추출**
3. 미입력자에게 입력 요청 문자 발송 — **입력 마감 기한 명시**
4. 마감 후 미응답자 **재안내**(전화 우선)
5. 수령한 여권값 검증
	- 여권 영문 철자·생년월일 **오타 확인**
	- 동행자(동반 인원) 누락 여부 확인
	- 인펀트(만 2세 미만 유아)는 여권/APIS 별도 처리 대상인지 확인
6. 검증 완료된 여권 영문명·생년월일을 STEP-27 PNR·APIS 제작 전까지 확정

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 독촉 문자 실문구는 CS 대응 문자 패턴에서 확정 후 링크(민증 수집용 단체문자 문구는 보험 단계 참고: 단체문자 여행자보험 멘트). '미입력자' 판정 항목 — 여권 영문·생년월일·여권번호·유효기간 중 어디까지 필수인지 예약 폼 구성에 맞춰 확정. 입력 마감 기한의 기준일(출국 D-? 또는 PNR 작업일 기준)과 재안내 횟수·간격.
</callout>

<callout icon="⚠️" color="red_bg">
	**여권 영문·생년월일 오타 = 발권 오류** 입력받은 여권 영문 철자와 생년월일이 틀리면 그대로 발권 오류로 이어진다. 수령값은 반드시 검증하고, 영문명은 STEP-27 PNR·APIS 제작 전에 확정한다.
</callout>

- 여권 미수집·미응답 칸을 **자의적으로 추정해 메우지 말 것** → 반드시 전화로 직접 확인(기존 민증 수집 노하우와 동일).
- 영문명 오타가 발권 이후 발견되면 항공사에 별도 변경 요청 양식이 필요하다(여권 영문명 변경 참고). 발권 전에 잡는 것이 최선.
- 발권 데드라인 역산: 여권 확보가 늦으면 STEP-27 PNR/APIS 일정이 밀린다. 미입력자 0 달성을 본 단계에서 마무리.

**핵심 용어**: APIS — 사전입국심사정보, 발권에 여권정보 필요(여권 없으면 임시번호 처리) · PNR — 항공 예약 기록, 여권 영문명 확정 후 제작 · 구글폼 — 공구별 신규 생성하는 여권정보 수집 폼 · 인펀트 — 만 2세 미만 유아, 여권·APIS 별도 처리 확인

**관련 문서**: STEP-17 예약 발신 템플릿 설정(여권 수집 폼 세팅) · STEP-25 중간 확정 안내 문자 · STEP-27 PNR·APIS 제작·항공사 공유 · 인펀트 APIS · 여권 영문명 변경(에어마카오) · CS 대응 문자 패턴 · 고객 예약 확정 프로세스

## STEP-27 · 항공 PNR(APIS) 생성 & 항공사 공유

여권·여정이 확정된 건만 추려 에어마카오·에어부산 PNR(APIS)을 생성·항공사에 공유하고, 구글 시트에 기록한다. 동시에 인플에 완료율 등 진행상황을 상시 공유한다. 오기입 시 금전 패널티.

**목적**
여권·여정이 확정된 건만 추려 에어마카오·에어부산 PNR(APIS)을 생성·항공사에 공유하고 구글 시트에 기록한다. 동시에 인플에 완료율 등 진행상황을 상시 공유한다. 오기입 시 금전 패널티.

**담당**
- 메인: 김용성

**절차**

선행: STEP-26(여권정보 미입력 문자) 회신분 유입 + STEP-24(72시간 후 해피콜·자동 확정)에서 확정된 건이 모인 상태에서 시작.

0. 확정 건만 추출
	1. **여권/여정이 모두 확정된 건만** 추출 (미확정·여권 미수신 건 제외)
		- 미확정·누락 건은 섞지 말고 STEP-26(여권정보 미입력 문자) 흐름으로 다시 수집

에어마카오 PNR (APIS) 생성

2. 에어마카오 담당자에게 여권 명단 전달 요청
3. APIS 시스템에서 생성 (Advanced Passenger Information System)
	- 여권 정보 없을 때: 임시번호 `m0000000` 입력
	- 유아(인펀트, Infant) 포함 시: 해당 승객 숫자에서 **INF로 수정 후 저장**
4. 생성 완료 후 구글 시트에 PNR 입력 + **세모(△) 표시**

에어부산 PNR 생성

5. 에어부산 전용 시스템 직접 입력
	- 입력 항목: 영문 성/이름, 생년월일, 성별, 여권 번호, 만료일
6. 구글 시트에 PNR 입력 + **세모(△) 표시**

더블체크

7. 영문명·생년월일·여권번호 전체 재확인 (혼자 하지 말고 동료 교차 확인)

항공사 공유 & 기록

8. 생성한 PNR(APIS)을 **항공사에 공유** (에어마카오=담당자 톡방 / 에어부산=단톡방 — 채널은 에어마카오 담당자 문의 참조)
9. 제작·공유 상태를 건별 기록 (제작완료 / 공유완료 / 미확정 보류)

인플 진행상황 공유 (상시)

10. 인플에 **완료율 등 진행상황을 상시 공유** (세일즈방 활용)

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 인플 진행상황 공유 채널·주기·양식(어디서 어떤 양식으로 완료율을 전달하는지) 사내 운영 기준 확정 필요.
</callout>

영문명 변경이 필요한 경우 (에어마카오) — 이미 발권된 항공권의 영문명 오류 수정. 에어마카오 담당자에게 아래 형식으로 요청.

```
<영문명 변경>

[현재 이름] KIM/CHULSU
항공권번호: 675XXXXXXXXX2
=> [정정 이름] KIM/CHEOLSU

해당건 확인 부탁드리겠습니다.
```

인펀트 포함 시 처리 (에어마카오 APIS)
- 인펀트(만 2세 미만)가 있는 경우 → 해당 승객 수에서 **INF로 변경 후 저장**
- 인펀트는 좌석 없이 보호자 무릎 탑승 → PNR은 보호자에 연결

<callout icon="⚠️" color="red_bg">
	**여권·여정 미확정 건은 제외** APIS는 여권정보가 정확해야 항공사 제출이 유효하다. 미확정·여권 미수신 건을 섞어 제작하면 정정·재제출이 발생한다. 확정 건만 추려서 제작하고, 누락·오류 건은 STEP-26(여권정보 미입력 문자) 흐름으로 다시 수집한다.
</callout>

- **오기입 시 변경 수수료 또는 전액 패널티 발생 → 무조건 더블체크**
- 에어마카오와 에어부산 PNR 생성 방법이 다름 — 혼동 금지
- 발권 후 영문명 변경은 수수료 발생 가능 → 처음부터 정확하게 입력하는 게 최우선
- 공구 종료 이후 **1주일 내** 완료 필수 (Deadline)
- 세모(△) 표시는 PNR 생성 완료 신호 — 빠트리면 추적 불가

**핵심 용어**: PNR — Passenger Name Record, 항공 예약번호 · APIS — 출국 전 항공사에 제출하는 승객 사전 정보 시스템 · 인펀트 — 만 2세 미만 영유아 승객 · 세일즈방 — 사내 영업 공유 채널(진행상황 공유)

**관련 문서**: 마카오 업무 흐름 정리(APIS 생성 상세) · 인펀트 APIS 처리 · 에어마카오 담당자 문의(영문명 변경 양식·공유 채널) · 여권 영문명 변경(에어마카오) · 고객 예약 확정 프로세스

## STEP-28 · 항공권·E티켓 & 호텔 예약번호 최종 확정 안내

에어마카오는 항공권 번호, 에어부산은 E티켓을 수령해 호텔 예약번호와 함께 고객별로 매칭·정리하고, 최종 예약 확정 안내 문자를 발송해 공구 fulfillment를 마무리한다.

**목적**
에어마카오는 항공권 번호, 에어부산은 E티켓을 수령해 호텔 예약번호와 함께 고객별로 매칭·정리하고, 최종 예약 확정 안내 문자를 발송해 공구 fulfillment를 마무리한다.

**담당**
- 메인: 김용성, 정민님

**절차**

1) 항공권 번호 / E티켓 수령
1. **에어마카오**: 에어마카오 담당자로부터 **항공권 번호(13자리)** 수령
2. **에어부산**: 에어부산 시스템에서 **E티켓(PDF)** 수령
3. 형식 혼동 금지 — 에어마카오 = 항공권 번호 / 에어부산 = E티켓 (PDF)
	- **에어마카오** — 발급 형태: 항공권 번호(13자리) / 발급 주체: 에어마카오 담당자 / 고객 전달: 번호 문자 전송
	- **에어부산** — 발급 형태: E티켓(PDF) / 발급 주체: 에어부산 시스템 / 고객 전달: PDF 첨부 발송

2) 호텔 예약번호 + 건별 매칭 정리
4. 항공권 번호(에어마카오) 또는 E티켓(에어부산) + **호텔 예약번호**를 고객별로 정리
5. 구글 시트에 **고객 ↔ 항공 ↔ 호텔** 매칭 입력
6. 고객 성명·여정 정보(날짜·편명·이름)를 다시 한번 **육안 재확인** (매칭 오류 방지)

3) 최종 확정 안내 문자 발송
7. 최종 예약 확정 안내 메시지 작성 (구성 내용은 아래 참고)
8. 고객에게 **개별 발송** — 출국일 기준 **1주일 전**
9. 요청 사항 있는 고객(전화 먼저 등) 확인 후 발송
10. 발송 후 해당 건 **동그라미(○) 체크** → 공구건 마무리
11. **전 고객 발송 완료** 확인 → 공구 fulfillment 종료

<callout icon="💡" color="gray_bg">
	**최종 확정 문자 구성 (포함 내용)** 고객님 항공권 번호(에어마카오) 또는 E티켓 첨부(에어부산) · 호텔 예약 번호 · 출국일·귀국일 · 기타 안내 사항(세미패키지 QR 등). 발송 타이밍: 출국일 1주일 전 기준.
</callout>

영문명 오류 수정이 필요한 경우 (에어마카오) — 항공권 발급 후 영문명 오류 발견 시 에어마카오 담당자에게 즉시 연락한다.

```
<영문명 변경>

[기존] HONG/GILDON
항공권번호: 675XXXXXXXXX1
=> [정정] HONG/GILDONG

해당건도 확인 부탁드리겠습니다.
```

<callout icon="⚠️" color="red_bg">
	**정보 매칭 오류 = 현장 사고** 고객별 매칭 오류 시 잘못된 정보 발송 → 대형 CS. 다른 고객 항공권 번호 발송 시 현장 탑승/체크인 사고로 직결. 발송 전 이름·여정·인원·확정번호(항공·호텔)를 건별로 대조 검수한다. 에어마카오 = 항공권 번호 / 에어부산 = E티켓 — 형식 혼동 금지. 고객이 그대로 제시·확인할 수 있는 형태로 정확히 적는다.
</callout>

- **중간확정** 문자(72시간 후 처리 단계)와 헷갈리지 말 것 — 이건 **최종** 확정.
- 영문명 변경은 수수료 발생 가능 → 발권 전 단계에서 처음부터 정확하게 입력.
- 발송 완료 후 반드시 ○ 체크 — **누락 방지**.
- **한 건이라도 미발송이 남으면 공구 종료로 처리하지 않는다.**

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 아래는 신 흐름 신규 항목으로 사내 실제 운영과 맞는지 확정 필요. "공구 종료" 처리의 정확한 정의(어떤 시트/상태값으로 닫는지). 발송 채널(문자/알림톡 등)과 발송 기록·보관 위치.
</callout>

**핵심 용어**: E티켓 — 에어부산 전자 항공권(PDF 형식) · PNR — Passenger Name Record, 항공 예약번호 · APIS — 사전 탑승자 정보 시스템(여권·여정 정보) · 중간확정 — 72시간 후 처리하는 1차 확정(최종 확정과 구분) · 세미패키지 — QR 발권 등 추가 안내가 따르는 패키지 형태 · 바우처 — 호텔 예약 확정 증빙

**관련 문서**: 고객 예약 확정 프로세스 · 예약 확정 문자 대응 원본 · 에어마카오 담당자 문의(영문명 변경 양식) · 여권 영문명 변경(에어마카오) · CS 대응 문자 패턴 · Phase 08 CS·예약 확정

## STEP-29 · 여행자보험 가입 (트래블로버)

고객·동행자 정보(민증 뒷자리 포함)를 수집해 트래블로버 B2B 사이트에서 단체 여행자보험을 가입 처리한다.

**목적**
고객·동행자 정보(민증 뒷자리 포함)를 수집해 트래블로버 B2B 사이트에서 단체 여행자보험을 가입 처리한다.

**담당**
- 메인: 김용성

**절차**

1) 민증 정보 수집 (단체문자) — 고객에게 본인 포함 동행자 전원의 주민등록번호(뒷자리 포함)를 받아 명단을 정리한다. 아래 멘트로 단체 발송.

```
안녕하세요 ㅁㅁX마카오 건으로 연락드린 예스트래블입니다.
즐거운 여행을 위해 해외여행자 보험 가입을 진행해 드리려 합니다.
답장 통해 본인포함 동행하시는 분들 주민등록 번호(뒷자리 포함) 명단 정리 해서 입력해 주시면 신속하게 처리해 드리겠습니다.
감사합니다.
```

발송 후 답장 확인 → 민증 뒷자리 없는 고객 → 전화로 직접 확인 (자의적 처리 금지)

2) 트래블로버 B2B 가입 (가입 절차)
접속 URL: [트래블로버 B2B]([내부 시스템 주소 삭제])

1. 상단 '여행자 보험 가입하기' 클릭
2. 여행정보 입력
	- 신청 담당자: **김민경**
	- 연락처: **노터치** (기존 정보 유지)
	- 이메일: `ot@yestravel.co.kr`
3. 여행자 보험 정보 입력
	- 보험 종류: **단기해외여행** 선택
	- 여행기간: 고객 여행 일정 입력
	- 여행 국가: **마카오**
	- '여행 가시는 분' 칸에 명단 붙여넣기
		- 입력 순서: **고객 이름 / 민증 / 영어이름** (동행자 포함)
	- 명단 전체 선택
4. '여행자 보험 플랜 선택하기' 버튼 클릭
5. **맨 왼쪽 오렌지색 보험 상품** 선택
6. 여행자보험 계약 확인 → 체크 후 패스
7. 결제 방법: **가상계좌** 선택 + 가입 동의 체크
8. 입금 은행: **기업은행** (노터치)
9. 현금영수증 발행
	- 지출 증빙용 선택
	- 발급방법: 사업자번호 → `315-87-02973`
	- 결제 진행
10. 결제 내역 확인 후 가상계좌로 이체
	- 이체 시 내 통장 인쇄 내용: **OO월 OO일 출발** 형식으로 기재 (예: 0410 출발)
11. 보험 가입 스프레드시트에 완료 고객 **노란색 색칠**
	- [보험 가입 스프레드시트]([내부 링크 삭제])

결제 카드 등 자격증명은 사내 보안노트 별도 — 담당자에게 요청.

<callout icon="⚠️" color="red_bg">
	**보험은 사고 시 보상·법적분쟁과 직결 — 실수 금지** 보험 가입 실수 → 실제 사고 시 보상 불가 → 법적 분쟁 가능. 민증 뒷자리 공백은 자의적으로 처리 금지 → 반드시 전화 확인. 결제 전 금액(이체금액) 반드시 재확인.
</callout>

<callout icon="⚙️" color="yellow_bg">
	**보완(확인필요)** 인펀트(만 2세 미만 유아) → 보험 가입 시 별도 처리 여부 확인.
</callout>

**핵심 용어**: 인펀트 — 만 2세 미만 유아(보험 가입 시 별도 처리 확인) · 공구 — 인플루언서 기반 마카오 여행 공동구매 건

**관련 문서**: 여행자 보험 가입 방법(원본 REF) · 단체문자 여행자보험 멘트 원본 · 고객 예약 확정 프로세스 · 보안노트(자격증명·카드)

## STEP-30 · QR 티켓 발권 (세미·특수패키지)

출국 3~5일 전, 세미패키지·특수패키지 고객에게 클룩 에이전트에서 QR 티켓을 발권해 전달한다. 일반 에어텔은 대상 아님.

**목적**
출국 3~5일 전, 세미패키지·특수패키지 고객에게 클룩 에이전트에서 QR 티켓을 발권해 전달한다. 일반 에어텔은 대상이 아니다.

**담당**
- 메인: 김용성, 정민님

**절차**
1. 출국일 **3~5일 전** 대상 고객 확인.
2. **세미패키지 또는 특수패키지 고객만** 필터링 (일반 에어텔은 QR 발권 대상 아님).
	- 어떤 패키지인지 STEP-28 최종 확정 내역(항공권번호·E티켓·호텔예약번호)으로 반드시 재확인.
3. 클룩 에이전트 사이트 접속 → QR 티켓 발권.
	- URL: `[내부 시스템 주소 삭제]`
	- ID: `info@yestravel.co.kr`
	- PW: 결제 카드 등 자격증명은 사내 보안노트 별도 — 담당자에게 요청
4. 발권한 QR 티켓을 고객에게 전달 (문자 또는 카카오).

<callout icon="⚠️" color="red_bg">
	**대상·타이밍 엄수** 세미패키지·특수패키지 고객만 해당 — 일반 에어텔 고객은 QR 발권 대상이 아니다. 출국일 기준 3~5일 전 발권 — 너무 이르거나 늦으면 안 된다. 패키지 구분이 헷갈리면 STEP-28 확정 내역으로 다시 확인할 것.
</callout>

- 클룩 에이전트 로그인 정보 외부 공유 금지 (자격증명은 사내 보안노트에만 보관 — 담당자에게 요청).

**핵심 용어**: 세미패키지 — 항공 + 호텔 + 일부 투어 포함 상품(QR 발권 대상) · 에어텔 — 항공 + 호텔 묶음 상품(QR 발권 대상 아님) · QR발권 — 클룩 에이전트에서 세미·특수패키지 투어 입장용 QR 티켓을 발권하는 절차

**관련 문서**: 클룩 에이전트 정보 원본 · STEP-28 항공권·E티켓·호텔번호 최종 확정 · 고객 예약 확정 프로세스 · Phase 08 CS·예약 확정 전체
