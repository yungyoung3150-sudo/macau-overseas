# 📌 STEP-16: 인플 구매 테스트 & 히든 공개 결정
> 인플이 실제로 결제 직전까지 구매 흐름을 밟아보게 해 이상이 없는지 검증하고, 오픈 시각까지 [[히든|상점을 히든]]으로 둘지 결정한다.

---
## 👤 담당자
| 역할 | 담당자 |
|------|--------|
| 메인 | 김용성 |
| 협업 | 정민 |
| 상세페이지 수정 | 팀장님 (문제 발견 시 요청) |

## 📋 절차
1. [[STEP-15|STEP-15]](품목·재고 셋팅·데일리 빼기) 완료 상태 확인 — 실제 구매 테스트가 가능한지 점검
2. **상세페이지 최종 QA** (구매 테스트 직전): 각 품목이 빠짐없이 첨부됐는지 순서대로 확인, 가격·일정·포함 내역 정확성 재확인 (기존 STEP-11 품목 재확인 — CS 폭발 방지용 필수 체크)
3. 인플에게 **구매 테스트** 안내 — 상점에 들어가 결제 직전까지 흐름을 밟아보도록 요청
4. 테스트 결과 이상 없는지 확인 — 품목·재고·옵션·금액 표시, [[후킹가|후킹가]]와 상세페이지 가격 일치 여부
5. 문제 발견 시 팀장님께 상세페이지 수정 요청 → 수정 완료 후 재확인
6. (테스트 시 [[JBS|JBS]] 예약 메시지가 정상 발송되는지 함께 확인 가능 — 본격 템플릿 교체는 [[STEP-17|STEP-17]])
7. **히든 vs 공개 결정**: 오픈 시각 전까지 [[히든|히든]] 상태로 두고, 오픈 시각에 맞춰 공개하도록 셋업
8. [[상점|상점]] **휴무 필요 여부** 판단

## ⚠️ 주의사항
> [!warning] 오픈 전 노출 사고
> 히든 처리를 빠뜨리면 오픈 시각 전에 상품이 외부에 노출될 수 있다. 테스트 직후 반드시 [[상점|상점]]을 [[히든|히든]] 상태로 되돌리고, 오픈 시각에 공개하도록 셋업했는지 재확인한다.

- **품목 누락 = 오픈 후 CS 폭발** → 구매 테스트 전 반드시 100% 체크 (기존 STEP-11 보존)
- 가격 오기입 특히 주의 — [[후킹가|후킹가]]와 상세페이지 가격이 불일치하면 고객 혼란
- ⚙️ 보완(확인필요): 구매 테스트 안내 시 인플에게 전달하는 멘트·범위(실결제 여부, 결제 직전 중단 지점 등) 표준화 — 근거 없는 수치/멘트 임의 생성 금지
