## 3. 핵심 포인트 / 참고

### 🖥️ 핵심 시스템·링크
- **[[JBS|JBS]] (Jungle Booking System)** — 품목관리·일정배치·카테고리 설정, 예약 메시지 템플릿까지 담당하는 판매 셋업 시스템.
  - 접속: `[내부 시스템 주소 삭제]`
  - 주 작업 공간은 **일정배치** 탭(날짜별 재고 수량). 일정배치는 보통 선임이 기본 틀을 잡아두며, 내 작업은 재고가 호텔 실재고와 일치하는지 확인·수정.
  - 상세: [[Jungle Booking system|Jungle Booking system]]
- **[[Janda 판매 사이트 & 스프레드시트 운영|Janda 판매 사이트 & 스프레드시트]]** — 판매 사이트·운영 스프레드시트 세팅.
- **호텔 부킹 사이트([[SCM|SCM]], shijicloud)** — 여행 날짜별 잔여 객실 직접 확인.
  - `[내부 시스템 주소 삭제]`
  - 조회법: [[SCM 부킹 조회 방법|SCM 부킹 조회 방법]]
- **에어마카오 모객현황 구글 스프레드** — `[내부 링크 삭제]`

### 🏪 상점·판매코드 (STEP-12·13)
- 이번 공구를 담는 [[상점|상점]]은 건마다 이름을 바꿔 재사용한다. **직전 공구명이 그대로 남으면** 고객이 이전 공구로 인식해 CS로 직결되므로 상점명 변경은 빠뜨리지 말 것.
- [[판매코드|판매코드]]는 이번 공구 상점 기준으로 새로 발급. **이전 공구 코드·링크 재사용 금지**.
- 코드 ↔ 상품·가격·링크 매핑을 눈으로만 보지 말고 **실제 클릭 테스트**로 정상 페이지 도달·정상 가격 노출까지 검증한 뒤 인플에게 전달. 코드 연결 오류는 오픈 직후 매출 손실로 직결.

### 📄 상세페이지 (STEP-14)
- 자체 HTML 편집기로 **상품별 themed 산출물**(galaxy-macau, lisboa-palace, selectum-noa 등) 제작 → [[상세페이지|상세페이지]].
- **가격·포함/불포함·유의사항은 반드시 노션(SoT)을 기준**. 상세페이지가 SoT이 아니므로 불일치 시 노션 우선 정정. [[후킹가|후킹가]]와 상세페이지 가격 불일치 특히 주의.
- ⚠️ 편집기 자동저장(window.name)이 소스 텍스트 직접 편집을 덮어쓸 수 있으니 라이브 동기화 주의.
- 패키지 유형: [[에어텔|에어텔]] 상품(항공+호텔+옵션) / [[세미패키지|세미패키지]](인플별 진행 여부 확인 필요).
- 소구포인트 작성 시 참고: 유류세 인상 부담 없음, 자유여행/세미패키지 선택 가능 여부(인플마다 다름), 지방(부산) 출발 명시, 객실 크기·호텔 퀄리티, 조식 포함 여부, 바우처 혜택(갤럭시 200MOP 쇼핑 바우처 등), [[인펀트|인펀트]] 추가 비용 → [[소구포인트|소구포인트]].

### 📦 품목·재고 (STEP-15) — 데일리 제외
- **[[데일리|데일리]](일별 재고)는 반드시 제외** 후 세팅. 포함하면 오류 발생.
- **항공 모객현황 확인 채널이 항공사마다 다름**: 에어마카오 = 모객현황 구글 스프레드 / 에어부산 = 단톡방에 확정 가능 여부 요청. 채널 혼동 주의.
- **호텔 SCM 객실 가용 확인 담당자**: 갤럭시(안다즈/브로드웨이) = 갤럭시 담당자님 / 리스보아 = 리스보아 담당 이사님.
- JBS 재고 ↔ 호텔·항공 실재고 불일치 시 **즉시 JBS에서 수정**, 가용 불가 일정은 즉시 제거. **SCM·모객현황 확인 없이 JBS 세팅 금지**(오버부킹 시 전액 보상 책임).
- 호텔 투숙 규정(재고 셋업 시 필수):
  - 안다즈 마카오 — 성인 3명↑ Extra Bed 자동 발생(원치 않아도). 시스템에 성인 3 입력 불가 → 성인 2+소인 1로 조회. Extra Bed 발생 시 갤럭시 어드민으로 이메일 발송 필수. 물량 부족 시 갤럭시 담당자님께 추가 물량 요청.
  - 브로드웨이 마카오 — 성인 2+소인 1이 MAX(엑스트라베드 공간 없음), 성인 3명이면 객실 2개 필요.
- 🃏 호텔 예약 결제 카드 종류는 MA. 카드 번호·만료일·명의는 본문에 쓰지 않고 사내 보안노트(자격증명은 담당자에게 요청)에서만 확인. 결제 금액(MOP)이 공구 스프레드 금액과 일치하는지 반드시 확인 후 결제.

### 🧪 구매 테스트·히든 (STEP-16)
- 인플에게 상점에서 **결제 직전까지** 구매 흐름을 밟아보게 해 품목·재고·옵션·금액 표시, [[후킹가|후킹가]]와 상세페이지 가격 일치 확인.
- 오픈 시각 전까지 [[상점|상점]]을 [[히든|히든]] 상태로 유지하고, 오픈 시각에 공개하도록 셋업. 히든 처리 누락 시 오픈 전 외부 노출 사고. 상점 휴무 필요 여부도 판단.

### 📝 예약 발신 템플릿 (STEP-17)
- 공구별 **여권 수집용 [[구글폼|구글폼]] 신규 생성**(이전 폼 재사용 금지) → JBS 예약 메시지 템플릿의 폼 링크를 새 폼으로 교체·활성화 → 테스트 예약으로 정상 발송 확인.
- 현재 사용 중 폼 링크(참고): 마카오 일반 `[내부 링크 삭제]` / 마카오 리스보아 `[내부 링크 삭제]`.
- 여기서 수집한 정보가 이후 [[STEP-26|STEP-26]](여권정보 미입력 문자)·[[STEP-27|STEP-27]](PNR [[APIS|APIS]] 제작)의 기준 데이터가 되므로 필수항목은 오픈 전에 고정.

### ⚠️ 이 PHASE의 사고 포인트 (요약)
- 직전 공구 상점명·코드·폼 링크가 남아 있으면 → 이전 공구로 연결되는 사고.
- 상세페이지 **품목 누락 = 오픈 후 CS 폭발** → 공구 시작 전 100% 체크.
- 가격 오기입(후킹가 ↔ 상세페이지 불일치) → 고객 혼란·클레임.
- SCM/모객현황 미확인 세팅 → 오버부킹 → 전액 보상 책임.
